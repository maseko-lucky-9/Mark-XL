- **Analysis (what the research-first pass bought us):** Reading the live Rust source corrected TWO briefing assumptions before they reached Development — (1) the real `TraceCollector` persist API is `start_trace`/`add_step`/`end_trace` (collector.rs), NOT an invented `record`; (2) the Rust `SchedulerStore` status vocabulary (`active/paused/cancelled/completed`, scheduler.rs:41-45) differs from the Python `TaskStatus` enum (`pending/running/completed/failed/cancelled`, task_queue.py:9-14) → the wrapper must BRIDGE without renaming either (FR-2). Both are captured in the contracts. This is the "verify by exercising/reading the source, not by export-name presence" lesson paying off again (the same discipline that surfaced the Phase-2 blocker).

- **Reflection (sharp carry-forwards for Development):** (1) FR-18 stays cheap — the WO-3 pass-bools-into-modules pattern keeps the `get_flag` allowlist at exactly `{main.py, agent/executor.py}` and leaves `test_flags.py` UNCHANGED; the only failure mode is a stray `get_flag` substring (even in a comment/docstring) in a new file — sweep for it. (2) WAL ownership is resolved concretely: Python runs `PRAGMA journal_mode=WAL` on the owned path BEFORE the Rust store opens it (the Rust ctor never sets WAL). (3) The session migration is a documented NO-OP today (flat-JSON FACT memory has no message log) but the `.bak` must be crash-safe (fsync + resume-from-bak). (4) One `[UNVERIFIED]` to close in Lane W: whether AC5b reads telemetry back via a new field-level accessor or via `TelemetryAggregator.stats()`+`count()` — the binding author must confirm against the Rust source.
